# Font-size accessibility audit — adityaaswani.com

Date: 2026-10-11. Requested by Aditya (2026-10-11 18:30 EDT): every piece of text large enough from an accessibility perspective.

## Method

Script: `scripts/font-size-audit/fontaudit.mjs` (Steel cloud browser, puppeteer-core) with this repo's page list in `scripts/font-size-audit/pages.mjs`; `report.mjs` writes this file. For every page at 390 px (phone, DPR 2) and 1280 px (desktop), light and dark, it walks every visible text node and records computed font-size, line-height, weight, letter-spacing, text-transform, colour, effective background, contrast ratio and role (heading / body / meta / control / input). It then raises the browser's default font size to 150% (CDP `Page.setFontSizes`) to find text in fixed px, and lays the page out at 125% and 150% zoom and with the 150% root size, checking horizontal overflow, clipped text and overlapping text. axe-core 4.10 runs `color-contrast`, `meta-viewport`, `meta-viewport-large`, `target-size`, `avoid-inline-spacing`.

Pages marked as emails are rendered from the product's own templates; email clients need px, so they skip the fixed-px and zoom checks but keep the size floors.

Flags: body text < 16 px on phone (< 15 px desktop) · meta/secondary/heading text < 14 px · any text < 12 px · labels on tappable controls < 14 px · form inputs < 16 px on phone (iOS zooms on focus) · body line-height < 1.4 · letter-spaced caps < 13 px · text that does not grow with the browser text size (fixed px). A flag is one distinct page × width × rule × selector × size; light and dark are merged.

| Body, headings, buttons, nav, root size | 1.0625 rem body, root 100% | unchanged |
